# StarTab — Starfall custom Minecraft player list

A lightweight custom TAB player-list plugin for **Paper 26.1.2**, with a cyan Starfall header and configurable ranked players matching the supplied screenshot. **Java 25 / Maven**.

## Features
- Configurable Starfall logo, multi-line header and footer
- Colored group prefixes; rank sorting; vanilla green ping bars
- LuckPerms groups/permissions and optional PlaceholderAPI
- Live player counts, online counts, ping and world
- `/stab info`, `/stab reload`
- Custom Nexo glyph asset (256×72 transparent PNG)

## Build and install
1. Run `mvn clean package` with **JDK 25**; or download the JAR generated by GitHub Actions on this repository.
2. Copy `target/StarfallTab-1.0.0.jar` into `plugins/` on Paper 26.1.2.
3. Restart; edit `plugins/StarfallTab/config.yml`; use `/stab reload`.
4. If you use Nexo, place `nexo/glyphs/starfall_tab.yml` in `plugins/Nexo/glyphs/` and the `nexo/pack/assets/` subtree in `plugins/Nexo/pack/assets/`. Rebuild and send the Nexo pack to players.
5. With Nexo + PlaceholderAPI enabled, set `logo: '%nexo_starfall_tab_logo%'` in StarfallTab's config. Without Nexo, the text STARFALL logo remains visible.

Do **not** run another TAB formatting plugin simultaneously unless its header/footer, sorting and player-name formatting features are disabled. This plugin does not change in-world nametags.

## Logo dimensions
- Current supplied PNG: **256×72 px** (transparent), using Nexo `height: 30`, `ascent: 25` (approx. 107×30 in-game GUI pixels)
- Suggested Aseprite canvas for a replacement logo: **256×72 px**.
- Other suggested assets: footer **256×32**, small logo **128×36**, rank icons **16×16**.
- Single bitmap font glyph dimensions must be at most 256×256. Larger designs require splitting into several glyphs.

The Minecraft client chooses TAB's number of columns based on player count and GUI scale. Four columns cannot be guaranteed with fewer online players. The original locally compiled JAR was built against development stubs and was not live-server verified; use the GitHub Actions build against the real Paper API for deployment.
